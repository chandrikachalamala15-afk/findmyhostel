2. The Execution Halls: Where Does Code Actually Run?

One of the most important concepts in computer software is knowing which machine runs which line of code. Code does not run in thin air — it runs inside specific Execution Halls:

Hall 1: The Browser Execution Hall (Client-Side)

Runs on User's Laptop / Phone

Who runs here: The Google Chrome V8 engine, Apple WebKit, or Firefox SpiderMonkey.

  • HTML Parsing: Converts <div>, <button>, and <table> tags into living visual elements on screen.
  • CSS Layout Calculation: Computes the glowing colors, cards, shadows, and flexbox grids from modern-theme.css.
  • JavaScript Execution: api-client.js runs right here inside the user's phone or computer memory! It listens for clicks, filters hostels by budget slider without reloading the page, and manages the interactive 7-day food timetable.

Hall 2: The Edge CDN Execution Hall (Cloud Gateway)

Runs on Netlify Global Edge Nodes

Who runs here: Netlify's high-speed distributed reverse-proxy edge servers located across the globe.

  • Static File Serving: Delivers pre-compressed HTML, CSS, JavaScript, and PDF files to visitors in under 50 milliseconds.
  • URL Rewriting (via netlify.toml): When a user types /hostels.html, the edge server rewrites the route to fetch the file directly from the public/ directory so there are never 404 errors.
  • SSL / HTTPS Encryption: Terminates TLS certificates to keep user passwords and messages safe from eavesdropping.

Hall 3: The Server Execution Hall (Backend PHP Engine)

Runs on Web Server / Port 8000

Who runs here: The PHP 8.x Interpreter on the host server (or your local computer).

  • URL Query Inspection: Inspects what the user asked for: action=list, city=Hyderabad, min_price=5000.
  • Security & Sanitization: Ensures no hacker can inject malicious code by whitelisting sort fields strictly to allowed columns.
  • CORS Headers: Sends permission headers allowing frontend browsers to talk to the backend safely.
  • JSON Encoding: Packs the final answers into a lightweight, standardized JSON packet and sends it across the wire.

Hall 4: The Database Execution Hall (MySQL Storage Engine)

Runs on MySQL Server / Port 3306

Who runs here: The MySQL 8.0 relational database engine (InnoDB).

  • Relational Table Queries: Joins the hostels table with the rooms table to calculate how many beds are vacant.
  • Indexing Scans: Quickly searches through thousands of records in milliseconds using indexed keys.
  • ACID Transactions: Guarantees that when a student reserves a room, two students cannot book the exact same bed at the same time.

3. The Data Journey: Where Data Originates and How It Travels

To understand the heart of Find My Hostel, let us trace two real-world journeys of data from start to finish:

3.1 Data Journey A: A Student Searches for Hostels under $8,000

[STEP 1: User Action in Browser] Student slides the budget bar to "$8,000" and clicks "Boys Hostel". api-client.js intercepts the change and prepares query: { type: 'boys', max_price: 8000 } | v [STEP 2: Network Transmission] Browser sends HTTP GET request: GET /api/hostel_controller.php?type=boys&max_price=8000 | v [STEP 3: Server Execution in PHP] hostel_controller.php parses inputs, validates type='boys', casts price to integer. Constructs SQL: SELECT h.*, MIN(r.rent_per_month) as min_rent FROM hostels h ... | v [STEP 4: Database Execution in MySQL] MySQL queries the 'hostels' and 'rooms' tables, filters records matching criteria, and returns 4 matching hostel rows to PHP. | v [STEP 5: JSON Packaging & Return] PHP formats rows into: { "success": true, "data": { "hostels": [...] } } Sends HTTP 200 OK back over the internet. | v [STEP 6: Visual Rendering in Browser] api-client.js receives JSON, loops through the hostels, builds HTML cards, and injects them into the page. The student sees the updated list in under 0.2 seconds!

3.2 Data Journey B: An Admin Marks a Complaint as "Resolved"

[STEP 1: Admin Click] Manager clicks "Mark Resolved" on Complaint #10 ("AC not cooling in Room 101"). | v [STEP 2: Network Request] Browser sends HTTP PATCH with JSON body: { "complaint_id": 10, "status": "resolved", "resolution_notes": "Compressor capacitor replaced" } | v [STEP 3: Controller Processing] complaint_controller.php verifies status is valid ('resolved'), captures timestamp, and executes: UPDATE complaints SET status = 'resolved', resolved_at = NOW() WHERE complaint_id = 10 | v [STEP 4: Database Write & Maintenance Ticket] MySQL updates the row on disk and logs an entry in the 'maintenance' table. | v [STEP 5: Instant Screen Update] Browser receives confirmation; badge turns from Yellow "Pending" to Green "Resolved".

3.3 The Smart Dual-Mode Fallback (Why the Website Never Breaks)

Architectural Resilience
When Find My Hostel is hosted on static cloud CDNs like Netlify or GitHub Pages, there is no active PHP/MySQL server attached. Instead of displaying ugly error screens or crashing, api-client.js detects this instantly and serves the data from an in-memory replica of the database! This means anyone testing the website on Netlify can search, filter, view the 7-day food menu, and test complaint status changes seamlessly.

4.2 The Styling System (public/css/modern-theme.css • 15 KB)

The entire visual personality of Find My Hostel is controlled by modern-theme.css. It uses modern CSS custom properties (variables) for consistent themes:

Key Design System Tokens

  • Color Palette: Deep twilight canvas background (--canvas-gradient: #1e1b4b → #3b82f6), vibrant electric blue accents (#4361ee), rich royal purple (#7209b7), and crisp white card surfaces (#ffffff).
  • Glassmorphism & Elevation: Smooth drop-shadows (--shadow-canvas-card) and subtle translucent borders that make cards float effortlessly over the background.
  • Responsive Breakpoints: Media queries at 1024px (laptops), 768px (tablets), and 480px (smartphones) that restructure multi-column grids into single-column mobile layouts automatically.
  • State Badges: Pre-styled pill badges for complaint states: .badge-pending (warm amber), .badge-in-progress (vibrant blue), and .badge-resolved (emerald green).

4.3 The Client Engine (public/js/api-client.js • 17 KB)

This script is the brain of the frontend. It exposes the global ApiClient object containing 5 core functions:

  • getHostels(filters): Fetches and filters hostels by search text, price, gender, and amenities.
  • getHostelById(id): Retrieves deep profile details, room breakdown, and the complete 7-day mess timetable.
  • getComplaints(filters): Retrieves the list of student maintenance issues for the admin portal.
  • updateComplaintStatus(id, status, notes): Updates an issue state to "in_progress" or "resolved".
  • submitEnquiry(data): Captures prospective student contact details and messages.

6.2 How It Runs Online on Netlify

The application is live on Netlify's high-speed Global Edge CDN. Here is how the deployment is configured:

The Configuration File: netlify.toml

[build]
  publish = "public"

[[redirects]]
  from = "/public/*"
  to = "/:splat"
  status = 301
  force = true
  • publish = "public" tells Netlify that the web files live inside the public/ folder.
  • The redirect rule ensures that typing /hostels.html or /admin.html directly works seamlessly without requiring any /public/ prefix.
